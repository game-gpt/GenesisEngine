# Genesis Engine

**因果引擎：为涌现式叙事与无限世界而生**

---

## 传统游戏引擎的死胡同

### 确定性快照的牢笼

所有传统游戏引擎（Unity、Unreal、Godot）都建立在同一个根本假设上：世界是一个**确定性快照的线性序列**。

```csharp
class WorldState {
    List<GameObject> AllObjects;   // 所有实体的确定状态
    float WorldTime;               // 全局统一时间
    Dictionary<string, bool> Flags; // 离散任务标记
}
```

这个模型有三个致命缺陷：

**状态空间爆炸**：每个对象在每一帧都必须有确定状态。一个"哥布林入侵村庄"事件，传统引擎必须实例化所有哥布林实体，无论玩家是否在看。

**时间的全局性**：`WorldTime` 是全局统一的。无法实现"玩家离开后村庄时间加速"的效果。远方和脚下共享同一个时间流速。

**因果的预设性**：任务标记只能表达"是否完成"，无法表达"玩家行为对世界命运的连续权重影响"。要实现"阅读所有图书馆藏书影响魔王台词"，需要程序员显式写 `if (booksRead >= totalBooks) { dialog = ... }`。

### 叙事的根本困境

所有传统 RPG 叙事都面临一个无法调和的矛盾：**玩家自由意志 vs 世界命运确定性**。

- **线性叙事**：世界命运是写死的。玩家行为只影响"是否到达结局"，不影响"结局的本质"。
- **分支叙事**：分支数量有限，因果逻辑是程序员预设的，不是涌现的。
- **开放世界叙事**：世界命运被"暂停"。奥杜因永远在等你去霍斯加高峰，灾厄盖侬永远在城堡里等你。

**共同病灶**：世界的"命运"是一个预渲染的动画，玩家的"行为"是一串输入指令。两者之间没有真正的因果纠缠，只有条件判断。

## 破局之路：从"预渲染"到"因果积分"

### 核心理念

> 世界不是一盒录像带，等你去播放。世界是一块概率云，你的每一个行为都在改变它的波函数。当你最终"观测"结局时，坍缩出的现实是你所有过往行为的因果积分。

这意味着：

- **没有"主线"与"支线"** 的区分。所有行为都是对世界波函数的修正。
- **没有"错过"** 的内容。未触发的任务以概率云的形式参与了最终坍缩。
- **没有"读档"** 的必要。每一个行为都不可逆地改变了世界的哈希链。

### 设计师角色的转变

在 Genesis 引擎范式下，游戏设计师的工作不再是"摆放每一棵树、书写每一句台词"，而是：

- **定义因果锚点**：玩家行为对世界命运的连续权重贡献。
- **设定初始条件与边界约束**：世界的初始资源分布、地理格局、宏观历史趋势的引力方向。
- **设计权重网络**：锚点之间如何相互影响、如何纠缠。

设计师从**世界的建造者**转变为**因果网络的编织者**。

## 时空四维树

### 唯一可行的数学结构

时空四维树是唯一同时满足以下四个条件的数学结构：

| 需求 | 描述 | 树结构的实现 |
|------|------|--------------|
| 叠加态 | 节点可处于"未坍缩"状态，只存储概率分布 | 树节点持有 `WaveFunctionState` 而非确定性数据 |
| 时间跳跃 | `Evolve(deltaTime)` 需 O(log Δt) 完成 | HashLife 算法的层级缓存 |
| 因果追踪 | 每个状态变化可追溯至其因果祖先 | Merkle 树结构的 `HistoryHash` |
| 分层精度 | 不同空间区域可有不同模拟精度 | 树结构天然的 LOD 能力 |

### 层级与时间膨胀

| 层级 | 空间尺度 | 时间尺度 | 相对时间流速 |
| :--- | :--- | :--- | :--- |
| L0 | 1x1x1 体素 | 1 tick (16ms) | 1x（基准） |
| L1 | 8x8x8 | 1 秒 | 60x 加速 |
| L2 | 64x64x64 | 1 分钟 | 3600x 加速 |
| L3 | 512x512x512 | 1 小时 | 216000x 加速 |

当玩家在 L0 层级活动时，L3 层级的时间以每小时一次的频率"滴答"一下。这一下滴答，就完成了整个大陆的演化演算。

## 因果锚点系统

### 从脚本到权重

设计师不再编写"剧情脚本"，而是定义**因果锚点**。

```yaml
因果锚点示例：
  - id: 拯救铁匠女儿
    权重: +5 希望
    影响终局: 解锁"铁匠的祝福"装备池
    影响坍缩: 魔王城攻城阶段，守军士气 +10%
    
  - id: 阅读所有图书馆藏书
    权重: +3 智慧
    影响终局: 解锁魔王的真名，可跳过第一阶段战斗
    影响坍缩: 魔王城谜题复杂度 -30%
```

### 核心玩法

玩家通过自由行为积累因果锚点 → 锚点之间发生权重纠缠 → 在关键叙事节点（观测时刻）坍缩出独一无二的故事。

---

## 波函数坍缩

### 从概率云到确定性

- **叠加态**：一个世界单元未被观测时，不持有单一确定值，而是持有一个概率分布。
- **坍缩**：当玩家注意力覆盖该单元时，系统根据当前上下文与历史哈希，从概率分布中采样一个确定状态。
- **纠缠**：相邻单元的状态受 WFC 约束传播影响，坍缩一个单元会导致邻居概率分布更新。

### 因果自洽性保证

坍缩出的状态必须与玩家已有的记忆一致。玩家交互过的区域被标记为**记忆锚点**，以确定性数据存储，永不进入叠加态。

## 注意力调度

### 注意力作为计算资源

- **屏幕空间**：玩家当前视野内的实体享受最高精度模拟（L0）。
- **交互范围**：玩家可立即触及的区域享受高优先级。
- **兴趣点**：玩家标记过的地点、任务目标周围享受次高精度。
- **历史轨迹**：玩家近期经过的路径保留一定精度的"回响模拟"。
- **其他一切**：进入低功耗的"概率云"状态。

这种调度方式可以将有效计算量削减 2~3 个数量级。

## HashLife 缓存

### 时间跳跃的数学基础

HashLife 算法证明，层级缓存可以将元胞自动机的演化从 O(Δt) 降为 O(log Δt)。

对于确定性规则（沙子下落、水流动、红石电路），Genesis 建立演化缓存。当一个区块被多次演化到相同的时间偏移量时，直接返回缓存的结果节点。

对于涌现性规则（植物生长、怪物生成），使用**种子哈希 + 伪随机函数**来模拟确定性缓存的效果。

## 规则系统

### 双重分类

| 类型 | 特点 | 计算模式 | 举例 |
| :--- | :--- | :--- | :--- |
| **确定性规则** | 输入输出严格对应；局部性；可缓存 | HashLife 加速 | 沙子下落、水流动、红石逻辑 |
| **涌现性规则** | 统计性、随机性；非局部影响；可近似 | WFC 坍缩 + 伪随机 | 草蔓延、火扩散、动物繁殖 |

## 渲染解耦

### 可插拔的渲染后端

Genesis 不绑定任何特定渲染技术。因果层输出：

```python
class CollapsedScene:
    entities: List[Entity]
    causal_features: Vector[float]  # 全局或逐实体
```

表现层只需实现一个函数：`render(scene: CollapsedScene) -> Frame`。

可选实现方案：
- 传统光栅化
- NeRF / 3D Gaussian Splatting
- 端到端扩散模型
- 混合渲染

## 设计公理

1. **状态的不确定性是创造力的土壤。** 只有当世界状态存在由玩家行为决定的"不确定性"时，探索与试错才有意义，个人化的发现与创造才可能发生。

2. **社会共识是虚拟世界真实性的唯一锚点。** 一个物品之所以有价值，是因为玩家社群共同相信它有价值。一个事件之所以是"历史"，是因为它被玩家社群共同见证、共同记忆。

3. **知识资产是终极的价值存储。** 在现实世界，财富的终极形式是能够创造更多财富的知识与关系网络。在 Genesis 构建的虚拟世界中，这一规律同样适用。

## 结语

Genesis 引擎不是对现有游戏引擎的改良，而是一次彻底的范式革命。

我们放弃了"计算一切"的幻想，转而拥抱"脑补一切"的智慧。层级区块、HashLife 缓存、WFC 坍缩……这些技术的本质，是在时间与空间的四维坐标系中，为每一个"可能性"分配一个数学地址。当玩家的注意力扫过时，引擎瞬间检索出那个最自洽的现实，呈现在屏幕上。

**Genesis 的名字寓意正在于此：**
**"起初，世界是一片概率的虚空。玩家的目光是光，于是有了天地、山河、草木、虫豸。每一次回眸，都是一次新的创世。"**

这，就是 Genesis 引擎的终极浪漫。
