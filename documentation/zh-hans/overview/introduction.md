# 项目介绍

## 什么是 Genesis 引擎

Genesis（因果引擎）是一套全新的游戏逻辑范式，以**时空四维树**与**因果锚点系统**为核心，专为涌现式叙事、活态世界和玩家驱动的命运演化而设计。

它从根本上放弃了传统游戏引擎"确定性快照 + 全局时间 + 预设因果标记"的架构，转而采用：

- **概率云叠加态**
- **注意力驱动的动态坍缩**
- **可追溯的 Merkle 因果哈希链**

## 核心哲学：从"预渲染"到"因果积分"

### 传统引擎的困境

所有传统 RPG 叙事都面临一个无法调和的矛盾：**玩家自由意志 vs 世界命运确定性**。

| 叙事类型 | 代表作 | 问题 |
|----------|--------|------|
| 线性叙事 | 《最终幻想》《巫师》 | 世界命运写死，玩家行为不影响结局本质 |
| 分支叙事 | 《底特律》《暴雨》 | 分支数量有限，因果逻辑是预设的 |
| 开放世界 | 《上古卷轴》《旷野之息》 | 世界命运被"暂停"，核心冲突永远等待玩家 |

**共同病灶**：世界的"命运"是一个预渲染的动画，玩家的"行为"是一串输入指令。两者之间没有真正的因果纠缠。

### Genesis 的解决方案

> 世界不是一盒录像带，等你去播放。世界是一块概率云，你的每一个行为都在改变它的波函数。当你最终"观测"结局时，坍缩出的现实是你所有过往行为的因果积分。

这意味着：

- **没有"主线"与"支线"的区分** — 所有行为都是对世界波函数的修正
- **没有"错过"的内容** — 未触发的任务以概率云形式参与最终坍缩
- **没有"读档"的必要** — 每一个行为都不可逆地改变了世界的哈希链

## 与传统引擎的对比

| 特性 | 传统引擎 | Genesis 引擎 |
|------|----------|--------------|
| 世界模型 | 确定性快照的线性序列 | 时空四维树 + 概率云 |
| 时间处理 | 全局统一时间 | 局部时间膨胀 |
| 因果追踪 | 离散任务标记 | 连续因果权重积分 |
| 状态存储 | 所有对象必须确定存在 | 未观测区域可处于叠加态 |
| 场景加载 | 预设静态资产 | WFC 算法动态生成 |

## 三大核心概念

### 1. 时空四维树（Spacetime Tree）

传统八叉树是 **3D 空间树**。时空四维树是 **3D 空间 + 1D 时间** 的树。

| 层级 | 空间尺度 | 时间尺度 | 相对时间流速 |
|------|----------|----------|--------------|
| L0 | 1x1x1 体素 | 1 tick (16ms) | 1x（基准） |
| L1 | 8x8x8 | 1 秒 | 60x 加速 |
| L2 | 64x64x64 | 1 分钟 | 3600x 加速 |
| L3 | 512x512x512 | 1 小时 | 216000x 加速 |

### 2. 因果锚点（Causal Anchors）

设计师不再编写"剧情脚本"，而是定义**因果锚点**：

```yaml
因果锚点示例：
  - id: 拯救铁匠女儿
    权重: +5 希望
    影响终局: 解锁"铁匠的祝福"装备池
    影响坍缩: 魔王城攻城阶段，守军士气 +10%
```

### 3. 波函数坍缩（Wave Collapse）

- **叠加态**：未观测区域持有概率分布或约束集合
- **坍缩**：玩家注意力覆盖时，从概率分布中采样确定状态
- **纠缠**：相邻单元状态受约束传播影响

## 设计师角色的转变

| 传统模式 | Genesis 模式 |
|----------|--------------|
| 编写剧情脚本 | 定义因果锚点的权重网络 |
| 设计分支树 | 设计权重纠缠规则 |
| 预设结局 | 让结局从因果积分中涌现 |

**核心玩法**：玩家通过自由行为积累因果锚点 → 锚点之间发生权重纠缠 → 在关键叙事节点坍缩出独一无二的故事。
